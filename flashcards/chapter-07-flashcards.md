## Chapter 7: LLM Integration and Deployment—Part 1: RAG, APIs, and Python Libraries — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | When is RAG (Retrieval-Augmented Generation) needed instead of fine-tuning? | RAG is needed when: 1) Data changes frequently (documents updated regularly), 2) Grounding in private/domain-specific data not in training set, 3) Need to cite sources, 4) Want to avoid expensive retraining. Exam tip: RAG for dynamic knowledge bases; fine-tuning for style/format adaptation. |
| 2 | What are the two main components of a RAG system? | 1) Retrieval: Vector database (FAISS, Pinecone, Weaviate) with embedding-based semantic search to find relevant documents. 2) Generation: LLM that uses retrieved documents as context to generate grounded responses. Exam tip: RAG = retrieve THEN generate, not retrieve OR generate. |
| 3 | Hugging Face Transformers: Load a pre-trained model for sequence classification (Python code) | from transformers import AutoModelForSequenceClassification, AutoTokenizer model = AutoModelForSequenceClassification.from_pretrained('bert-base-uncased') tokenizer = AutoTokenizer.from_pretrained('bert-base-uncased') Exam tip: Use AutoModel* classes—they auto-detect architecture. For tasks, use AutoModelFor* (e.g., ForSequenceClassification). |
| 4 | Hugging Face pipeline() vs model.generate()—when to use each? | pipeline(): High-level, task-specific (e.g., pipeline('text-generation'))—handles tokenization, inference, post-processing automatically. Easiest for common tasks. model.generate(): Low-level control over generation parameters (temperature, top_k, top_p, num_beams). Use when customizing sampling behavior. Exam tip: pipeline for simplicity; generate() for control. |
| 5 | LangChain: What does ConversationBufferMemory do? | Stores entire conversation history (all messages) in memory and injects into prompts. Simple but token count grows with conversation length. Alternative: ConversationSummaryMemory (summarizes history to save tokens). Exam tip: Buffer = verbatim storage; Summary = compressed storage. |
| 6 | LangChain chains: LLMChain vs RetrievalQA vs SequentialChain | LLMChain: Single LLM call with prompt template. RetrievalQA: RAG pattern—retrieve docs + LLM answer. SequentialChain: Run multiple chains in sequence, passing outputs forward. Exam tip: RetrievalQA for document Q&A; SequentialChain for multi-step workflows. |
| 7 | Vector database: Exact k-NN vs Approximate Nearest Neighbor (ANN) search | Exact k-NN: Computes distance to all vectors—accurate but slow (O(n)). Not viable at millions of vectors. ANN (HNSW, IVF): Uses indexing to search subset—fast (<100ms at scale) with ~95-99% recall. Exam tip: ANN required for production RAG at scale (>100K vectors). |
| 8 | FAISS IndexFlatL2 vs IndexIVFFlat—key difference? | IndexFlatL2: Exact search, brute-force L2 distance to all vectors. 100% recall, slow at scale. IndexIVFFlat: Approximate search, clusters vectors (IVF = Inverted File), searches nearest clusters only. Faster, ~90-95% recall. Exam tip: Flat for accuracy/small datasets; IVF for speed/large datasets. |
| 9 | Self-hosted LLM inference vs API calls—primary cost trade-off? | API: Cost scales linearly with usage ($/token). Low fixed costs, high marginal costs. Self-hosted: Fixed GPU rental costs (~$900-3000/month), low marginal costs. Exam tip: API cheaper at low/variable volume; self-hosted cheaper at high/predictable volume. Crossover ~500K-1M requests/month. |
| 10 | Generate diverse text with Transformers: which parameters prevent repetition? | top_k=50, top_p=0.9 (nucleus sampling): Sample from filtered token distribution. temperature=0.7-1.0: Controls randomness (higher = more random). do_sample=True: Enables sampling instead of greedy. Exam tip: Low temp/greedy → repetitive. Sampling + moderate temp → diverse. |
| 11 | Embedding model quality impact on RAG retrieval accuracy? | Better embeddings (larger models, domain-specific) capture semantic meaning more accurately → better vector similarity → relevant documents rank higher. Example: all-MiniLM-L6-v2 (384d, fast) vs all-mpnet-base-v2 (768d, more accurate). Exam tip: Model quality is #1 factor in retrieval accuracy before tuning k or index type. |
| 12 | LangChain Agent: What is it and when to use? | Agent: LLM that decides which tools to use and in what order based on reasoning (ReAct pattern). Use when: Task requires multi-step reasoning, tool selection (search, calculator, APIs), or dynamic workflow. Exam tip: Agents for complex reasoning; Chains for predefined workflows. |
