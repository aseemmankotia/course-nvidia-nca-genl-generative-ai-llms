## Chapter 8: LLM Integration and Deployment—Part 2: The NVIDIA Software Stack — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | What are the four main modules in NVIDIA NeMo's modular design? | 1) Data preprocessing, 2) Model training, 3) Prompt learning (P-tuning, prompt tuning), 4) RLHF (Reinforcement Learning from Human Feedback). Exam tip: NeMo is end-to-end framework—data to deployment. If question asks about building custom LLMs from scratch, NeMo is the answer. |
| 2 | NVIDIA NIM vs TensorRT-LLM: what's the difference? | NIM = pre-built containers for deploying optimized LLMs (ready-to-run microservices). TensorRT-LLM = library for optimizing transformer models (you build the optimization). Exam tip: NIM for fast deployment, TensorRT-LLM for custom optimization pipelines. |
| 3 | What three key optimizations does TensorRT-LLM provide? | 1) Quantization (INT4, INT8, FP8), 2) Kernel fusion (combining operations), 3) FP8 support for H100 Tensor Cores. Exam tip: TensorRT-LLM is the optimization layer—if question mentions quantization or kernel fusion for inference, it's TensorRT-LLM. |
| 4 | Triton Inference Server: name 4 production features | 1) Dynamic batching (auto-groups requests), 2) Concurrent model execution (multiple models simultaneously), 3) Model versioning (A/B testing), 4) Health checks. Exam tip: Multi-model serving + production features = Triton, not NIM or TensorRT-LLM. |
| 5 | What does Triton's dynamic batching do? | Automatically groups incoming requests into batches to maximize GPU utilization. Configurable with max_queue_delay_microseconds and preferred_batch_size. Exam tip: Prevents head-of-line blocking—small requests aren't delayed by large ones when configured properly. |
| 6 | NIM's three main benefits for LLM deployment? | 1) Reduced latency (TensorRT-LLM optimizations built-in), 2) GPU memory optimization (KV cache optimization, memory pooling), 3) Automatic batching (handles variable workloads). Exam tip: NIM = production-ready with minimal config. Pre-optimized containers. |
| 7 | CPU vs GPU inference: typical latency difference for LLMs? | GPU is 10-20x faster. Example: 45ms/token (CPU) vs 3ms/token (A100 GPU). Exam tip: Cost per token matters more than hardware cost—GPUs serve more tokens/second/dollar despite higher instance cost. |
| 8 | What parallelism strategies does TensorRT-LLM support for multi-GPU inference? | 1) Tensor parallelism (split layers across GPUs), 2) Pipeline parallelism (distribute layers across GPUs). Supports multi-GPU and multi-node. Exam tip: For scaling LLM inference across 4+ GPUs, TensorRT-LLM handles the parallelism. |
| 9 | Which NVIDIA tool for building custom LLMs from scratch? | NVIDIA NeMo. Provides data preprocessing, model architecture templates (GPT, BERT, T5), training infrastructure, and fine-tuning. Exam tip: 'Build from scratch' or 'custom domain' = NeMo. 'Deploy existing model' = NIM. |
| 10 | What frameworks does Triton Inference Server support? | PyTorch, TensorFlow, ONNX, TensorRT, and custom backends. Multi-framework support is a key feature. Exam tip: If scenario has multiple model types (PyTorch + TensorFlow), Triton can serve both on same infrastructure. |
| 11 | What is KV cache optimization in NIM? | Efficient storage and reuse of key-value pairs from transformer attention layers. Reduces memory fragmentation and enables longer sequences. Exam tip: If OOM errors occur despite low memory utilization, KV cache optimization in NIM reduces fragmentation. |
| 12 | NeMo's RLHF support: what does it enable? | Reinforcement Learning from Human Feedback for safety alignment and preference tuning. Part of NeMo's modular training pipeline. Exam tip: If question mentions 'safety alignment' or 'human preference tuning' during training, NeMo's RLHF module is the answer. |
