## Chapter 2: Transformer Architecture and Large Language Models — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | In multi-head attention with 8 heads and embedding dimension 512, what is each head's query/key/value dimension? | 64 dimensions (512 ÷ 8). Each head operates independently on a slice of the embedding space, then outputs are concatenated. Exam tip: Always divide embedding_dim by num_heads. |
| 2 | Decoder-only (GPT) vs encoder-decoder (T5): which for open-ended text generation? | Decoder-only (GPT). Encoder-decoder is better when input differs from output (translation, summarization with source context). Decoder-only excels at continuation/generation. Exam tip: Encoder-decoder = distinct input/output, Decoder-only = continuation. |
| 3 | What happens to attention in transformers if positional encoding is removed? | Model becomes permutation-invariant—cannot distinguish token order. 'dog bites man' = 'man bites dog'. Attention scores depend only on content, not position. Exam tip: No positional encoding = order-blind model. |
| 4 | Causal Language Modeling (CLM) vs Masked Language Modeling (MLM): which for GPT-style models? | CLM. GPT predicts next token given previous tokens (left-to-right, causal). MLM (BERT) predicts masked tokens using bidirectional context. Exam tip: CLM = generation (decoder-only), MLM = understanding (encoder-only). |
| 5 | Why is attention scaled by 1/sqrt(d_k) before softmax? | Prevents saturation. Dot products grow proportional to d_k (key dimension), pushing softmax into regions with tiny gradients. Scaling keeps values moderate. Exam tip: Scaled dot-product attention divides by sqrt(key_dim). |
| 6 | Model has 2048 context window. Prompt is 2000 tokens. How many tokens can be generated in one pass? | 48 tokens (2048 - 2000). Context window = total capacity for prompt + generation. Exam tip: Available generation = context_window - prompt_length. |
| 7 | BPE tokenizer: 1000 characters → 250 tokens. What does this indicate? | Normal BPE compression. Merges frequent character sequences into subword units. Avg 4 chars/token. Lower token count than character count is expected. Exam tip: Subword tokenization compresses text, fewer tokens than characters. |
| 8 | Encoder-decoder architecture: which part processes input context, which generates output? | Encoder processes input bidirectionally (sees full context). Decoder generates output autoregressively (left-to-right). Cross-attention connects them. Exam tip: Encoder = understand context, Decoder = generate response. |
| 9 | What are the three matrices in self-attention and their role? | Query (Q): what I'm looking for. Key (K): what I offer. Value (V): what I return. Attention = softmax(QK^T/sqrt(d_k)) × V. Exam tip: Q searches, K is searched, V is retrieved content. |
| 10 | Purpose of multi-head attention having multiple parallel heads vs single attention? | Different heads learn different attention patterns (syntax, semantics, long-range, local). Ensemble of perspectives. Outputs concatenated then projected. Exam tip: Multi-head = parallel diverse attention patterns, single = one pattern. |
| 11 | Autoregressive generation: what does the model output at each step? | One token at a time. Each new token is appended to input, model predicts next token. Continues until max length or stop token. Exam tip: Autoregressive = sequential token-by-token, not parallel generation. |
| 12 | WordPiece vs BPE vs SentencePiece: key difference in how they handle unknown words? | All are subword tokenizers that decompose into smaller units (no OOV). BPE: merge frequent pairs. WordPiece: merge based on likelihood. SentencePiece: treats input as raw byte stream (no pre-tokenization). Exam tip: All three avoid OOV through subword splitting. |
