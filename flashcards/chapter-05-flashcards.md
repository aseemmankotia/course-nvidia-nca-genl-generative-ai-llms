## Chapter 5: Data Preprocessing, Feature Engineering, Analysis and Visualisation — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | What is the recommended class weight formula for an imbalanced dataset with 10,000 positive and 1,000 negative samples? | Negative class weight = 10,000/1,000 = 10, Positive class weight = 1. Formula: weight = total_samples / (n_classes × class_samples). Exam tip: Weight inversely proportional to frequency. In PyTorch: use class_weight parameter in CrossEntropyLoss. Common mistake: weighting majority class higher makes imbalance worse. |
| 2 | Standard perplexity value for t-SNE visualization and when to adjust it? | Perplexity = 30 is standard (range 5-50). For small datasets (<100 samples): use 5-15. For large datasets (>10,000): use 50-100. Perplexity roughly means 'number of nearest neighbors to consider'. Exam tip: Too low = disconnected points, too high = everything bunches up. Always run 1,000+ iterations for convergence. |
| 3 | What percentage of token replacement is recommended for data augmentation using synonym replacement? | 10-15% replacement rate. Higher rates (>20%) risk changing meaning or creating ungrammatical text. Exam tip: Back-translation is more robust than synonym replacement. For contextual replacement using MLM: 15% max (matches BERT's pretraining). Rule: augmentation should preserve label correctness. |
| 4 | When should you use NFKC vs NFC Unicode normalization? | NFKC: For NLP/ML on noisy social media, multilingual text - applies compatibility mappings (Ａ→A, ₂→2). NFC: For preserving text fidelity in formal documents - keeps compatibility distinctions. Exam tip: NFKC = aggressive normalization for ML, reduces vocab. NFC = safer for human-readable text. Most modern tokenizers use NFKC internally. |
| 5 | Compare vocabulary size and sequence length trade-offs: word-level vs BPE vs character-level tokenization. | Word-level: Vocab=50K-100K+, shortest sequences, many [UNK]. BPE: Vocab=32K-50K, medium sequences, no [UNK]. Character-level: Vocab=256-500, 10-20x longer sequences. Exam tip: BPE is optimal for most LLMs (GPT uses BPE, BERT uses WordPiece which is similar). Pick BPE for unknown vocab/domains. |
| 6 | When should you use oversampling vs undersampling vs class weighting for imbalanced data? | Class weighting: Default choice, no data loss, works with any ratio. Oversampling (SMOTE): When minority class is tiny (<500 samples) but you need more data. Undersampling: When majority class is massive (>1M) and minority is large enough (>10K). Exam tip: Class weighting is most common in LLM fine-tuning. Never undersample if total data <10K samples. |
| 7 | What is the attention mask in transformer tokenization and why is it needed? | Binary mask [1,1,1,0,0] where 1 = real token, 0 = padding. Tells model which tokens to attend to. Without it, model attends to padding and learns garbage. Exam tip: Padding token gets mask=0. In batching, sequences are padded to max length in batch. Attention mask ensures padding doesn't affect loss calculation or predictions. |
| 8 | What is the sliding window overlap recommended when chunking long sequences? | 128-256 token overlap for 512-token windows. Prevents losing context at boundaries. Example: For 1,024-token doc with 512 window: [0:512], [384:896], [768:1280] gives 128-token overlap. Exam tip: Overlap = 25-50% of window size. No overlap risks losing information where sentences span chunks. Too much overlap = redundant computation. |
| 9 | Common preprocessing sequence for user-generated text before LLM tokenization? | 1) Remove HTML tags, 2) Lowercase (unless casing matters), 3) Remove URLs, 4) Remove/handle emojis, 5) Apply Unicode normalization (NFKC), 6) Remove extra whitespace. Exam tip: Order matters - clean HTML before lowercasing, normalize Unicode last. Don't apply stemming/lemmatization for subword tokenizers - they handle morphology. |
| 10 | How to identify mislabeled data using ensemble methods? | Train 5+ models independently. Flag samples where all models disagree with the label. Manually review flagged samples. Catches 70-80% of errors. Exam tip: This is supervised outlier detection. Alternative: confident learning (cleanlab library) uses predicted probabilities. Don't just remove flagged samples - relabel them. |
| 11 | Best EDA visualizations to perform before fine-tuning an LLM on classification data? | 1) Class distribution (bar chart), 2) Sequence length distribution (histogram), 3) Token frequency (top 50 words), 4) Vocabulary size vs frequency (Zipf curve). Exam tip: Look for: class imbalance (>3:1 ratio), sequence length outliers (>95th percentile), rare tokens that might need special handling. Use these to decide truncation/padding strategy. |
| 12 | What is the memory complexity difference between 512-token and 2,048-token sequences in transformers? | Attention is O(n²). 2,048 tokens = 16x more memory than 512 tokens for attention computation alone (4²=16). Total memory ~4-8x higher due to other operations. Exam tip: Doubling sequence length quadruples attention memory. This is why most models cap at 512-2,048 tokens. Gradient checkpointing saves ~50% memory but slows training 20%. |
